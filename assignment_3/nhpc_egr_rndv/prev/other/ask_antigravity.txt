## Eager Protocol — Partially Correct, But Has a Serious Problem ⚠️

**Small sizes (4KB–65KB): reasonable but slower than MPI**
This is expected. Your eager path has overhead:
- Extra copy into/out of the pre-allocated buffer
- CQ polling overhead
- RDMA setup cost not amortized at small sizes

MPI's eager protocol is highly optimized, so being 4–30x slower here is not alarming for a first implementation.

**Large sizes (262KB+): catastrophically slow 🚨**

| Size | Eager | MPI |
|------|-------|-----|
| 262KB | 1047 µs | 29 µs |
| 524KB | 3136 µs | 57 µs |

This is roughly **75x slower than MPI at 4MB**. This strongly suggests a bug in your chunking logic. Recall the assignment said:

> *"divide the user buffer into smaller chunks as preallocated buffers may only be of smaller size, say 128KB"*

What's likely happening is one of:

1. **You're doing the chunking serially with a wait after every chunk** — so for 512KB you're doing 4 round-trips instead of pipelining. Each chunk completes before the next starts, multiplying latency.
2. **Your CQ polling on the receiver side is spinning too long** between chunks — perhaps a timeout or a missed completion causing retries.
3. **Memory registration is happening per-send** instead of being done once in `myverbs_init`, which would be very expensive.

The roughly **linear growth** (262K→524K→1M→2M→4M latency roughly doubles each time) actually suggests it's doing correct work — just with O(n/chunk) sequential round trips. So the chunking itself probably works, but it's not pipelined.

## Rendezvous Protocol — Looks Correct in Shape ✅, But Check the Baseline

**The trend is right:**
- Nearly flat latency for small-to-medium sizes (~123–150 µs)
- Grows smoothly for large sizes

For small messages this overhead dominates, which is why rendezvous is typically only used above a threshold (often 16KB–64KB in real MPI implementations).

**Concern — the baseline ~123 µs overhead:**
That's your rendezvous handshake cost. For a loopback or single-switch IB setup, this seems a bit high. Check:
- Are you doing the rkey/address exchange **per call** to `myverbs_send`? You should be, since each call has a new user buffer to register.
- Is your `RDMA Write with Immediate` completion being properly waited on via CQ poll?

**Crossover point:**
Your rendezvous beats eager somewhere around **128KB–262KB**, which is realistic. Real MPI implementations typically cross over around 16–64KB, so your threshold is a bit high — likely due to the ~123 µs fixed cost.
